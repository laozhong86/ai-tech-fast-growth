# 首帧图与封面完整性多维质检门禁 (First-Frame & Cover Inspection Gate)

在各大短视频平台（微信视频号、抖音、小红书等）中，系统在视频上传后默认抓取视频文件的 **第 0.0 秒（第一帧）** 作为信息流中未播放状态下的静态缩略图与封面。本门禁旨在彻底消灭“黑屏废片封面”，并将“第 0 秒首帧封面 (`cover.png`)”固化为无需任何外部商业生图 API 的**开箱即用核心交付物**。

---

## 一、 核心定位：第 0 秒首帧即完整封面交付物

1. **痛点与传统成本**：
   * 传统短视频剪辑往往在片头设置“淡入（Fade In）”，导致视频第 0.0 秒处于全黑或半透明暗态，平台抓取的封面直接变成死黑框，点击率断崖式下跌；
   * 许多制作工具为了弥补这一缺陷，强行要求用户开通付费商业生图 API（如 GPT Image 2 / Midjourney），或者让用户手动暂停视频截图裁切，大幅拉高门槛与使用成本。
2. **零成本极简解决方案**：
   * **渲染端底层铁律**：视频片头的第一个镜头在 `t=0.0s` 处必须**立即以 100% 不透明度呈现完整媒体**，绝对禁止在片头设置任何形式的视频淡入暗化（`video fade-in = 0`）；
   * **成片出炉即出封面**：成片渲染完毕后，流水线自动以原始 1080×1920 尺寸导出 `cover.png`，作为独立交付物与成片一并归档，创作者在各平台发帖时可直接作为高质量静态封面上传使用！

---

## 二、 自动化双指标质检标准与算法门禁

成片导出后，质检模块自动提取 `t=0.0s` 首帧图，并对中央媒体视窗矩形 `(x=72, y=560, w=936, h=526)` 执行算法级门禁扫描：

| 质检维度 | 判定指标 | 合格阈值要求 | 业务含义与拦截逻辑 |
| :--- | :--- | :---: | :--- |
| **1. 画面亮度 (Luminance)** | 中央媒体视窗平均灰度值 | **$\ge 25.0$** | 彻底拦截因片头黑屏淡入造成的死黑暗帧。低于此值视为无效画面，直接阻断。 |
| **2. 丰富度 (Texture Std)** | 中央媒体视窗像素标准差 | **$\ge 12.0$** | 确保首帧包含真实内容、文字标题或界面截图，而非大面积未加载的纯色死块或空白。 |

---

## 三、 质检流程与成果归档

```text
[视频渲染完成 (片头严格零淡入)]
            │
            ▼
[自动抽取第 0.0 秒 1080×1920 首帧图 cover.png]
            │
            ▼
[多维算法审查：平均亮度 ≥25.0 且 纹理丰富度 ≥12.0]
            │
            ├─► 双指标均达标 ──► 标记质检通过 (First-Frame Pass)
            │                     │
            │                     ▼
            │               【交付核心资产】
            │               ├─ 1080×1920 高清成片 (.mp4)
            │               └─ 开箱即用高清封面图 (cover.png)
            │
            └─► 任一指标未达标 ──► 拦截报警 ──► 检查素材源与片头转场
```

通过这一轻量化机制，创作者无需任何繁重的外部依赖与商业付费，在出片的同时就能获得一张画面饱满、排版讲究、具备极强推流潜力的封面大图。
